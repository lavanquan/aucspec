# Runtime "V1-batchwall-tritonfa33"

Corrected ROCm verifier runtime: vLLM 0.9.1 **V0 engine** with **Triton FlashAttention** (`VLLM_USE_TRITON_FLASH_ATTN=1`)
using the Triton 3.3.1 that ships with torch 2.7.1. The legacy runtime (`VLLM_USE_TRITON_FLASH_ATTN=0`, no `flash_attn`
package) falls back to a naive SDPA path that is numerically wrong for three or more sequences per prefill step
(see `results/ROCM_BATCHED_INFERENCE_FAULT_ISOLATION.md`).

Why a shim: the project user-site (`PYTHONUSERBASE`) contains Triton 3.8.0, which shadows torch's 3.3.1 and breaks the vLLM Triton FA kernel.
`setup_shim.sh` creates one symlink, `<shim>/triton -> /usr/local/lib/python3.12/dist-packages/triton`; the launcher puts the
shim first on `PYTHONPATH`. No package is installed or removed.

* `setup_shim.sh` - idempotent, refuses to overwrite a different link. Default location (persistent, not purged):
  `/software/projects/pawsey1257/quanla/aucspec_runtime/tritonfa33/shim`.
* `MANIFEST.json` - expected versions, import paths and sha256 of the files that decide the attention kernel
  (generated by `scripts/runtime_manifest.py` inside the job environment; regenerate only with review).
* `scripts/preflight_runtime.py` - run on the compute node before work starts; exits 65 on any mismatch.
* `edge_specsim/runtime_guard.py` - run inside the simulator process after the engine exists: V0 engine, 28/28 layers Triton FA,
  0 naive layers, `max_logprobs=1`, original V1 tie-break, prefix caching off; counts Triton FA calls.
* Dependencies (pandas, PyYAML, ...) are frozen in the manifest; canonical jobs never run `pip install`.
